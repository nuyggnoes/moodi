Moodi 화면 설계, 이렇게 접근하세요                                                                                                                       
                                                                                                                                                           
  설계 순서 (4단계)                                                                                                                                        
                                                                                                                                                           
  1. 사용자 시나리오를 언어로 먼저 써라                                                                                                                    
  화면부터 그리지 말고, "퇴근길 지하철에서 지금 감정을 기록하고 싶다" 같은 구체적인 시나리오 3~5개를 문장으로 쓰세요. 그러면 페이지 이동 흐름이 자연스럽게 
  나옵니다.
  2. 각 페이지의 단 하나의 목적을 문장으로 정의해라
  예: /record는 "지금 이 순간의 감정과 음악을 빠르게 포착하는 것". 이게 명확해야 화면에서 뭐가 크고 작아야 하는지가 결정됩니다.
  3. 정보 계층을 손으로 박스만 그려라
  색상, 폰트 없이 "무엇이 위에 있어야 하나, 얼마나 커야 하나"만 스케치.
  4. 그 다음에 인터랙션 설계
  탭/스와이프/버튼 눌렀을 때 무슨 일이 벌어지는지.

  ---
  Moodi에서 특히 중요한 UX 포인트

  - 감정 기록의 마찰을 최소화: /record는 2~3번 탭으로 완료 가능해야 함. 기록은 가벼운 행위여야 합니다.
  - 앨범 아트가 감성의 중심: 단순 썸네일이 아니라 화면 분위기 자체를 결정. 색감을 배경에 번지게 하는 방식 고려.
  - 피드는 공감의 장: 좋아요 숫자보다 기분 태그와 앨범 아트가 먼저 눈에 들어와야 함. (친구 피드는 팔로우 기능 이후 — 지금 `/`는 내 주간 기록 화면)
  - 다크 톤 방향 초기 결정: 음악은 밤에 많이 들으므로 다크 감성이 잘 맞을 가능성 높음.

  페이지별 핵심 결정 포인트

| 페이지 | 핵심 결정 | 상태 |
|---|---|---|
| `/` | 카드 1개 크게 vs 여러 개 나열 | **결정됨** — 내 최근 7일 주간 포스터 캐러셀(가운데 포스터 강조, 무드 색이 배경으로 번짐). `docs/design/home-mockup.html`, `docs/spec.md` §5 |
| `/record` | 곡 먼저 선택 vs 기분 먼저 선택 | **결정됨** — 곡 먼저, 그다음 메모, 그다음 기분(AI 제안은 메모를 따라간다). 메모를 기분 위로 올리는 변경은 #57에서 적용했다. 레이아웃은 왼쪽 라이브 포스터 미리보기 + 오른쪽 폼(`docs/design/record-mockup.html` A안). 모바일 세부 레이아웃은 후속 |
| `/diary` | 달력 셀에 앨범아트 썸네일 vs 기분 색상 vs 숫자만 | **결정됨** — 기분 색상 |
| `/search` | 검색 전 빈 화면에 뭘 보여줄지 | **결정됨(음악 검색)** — 최근 검색어, 없으면 안내 문구. 유저 검색은 미착수 |
| `/profile` | 음악 정체성을 앨범아트 그리드 vs 기분 통계 vs 달력 미니맵으로 표현 | **미결** — 팔로우·프로필 기능을 시작할 때 정한다 |

※ 위 결정은 구현하면서 확정된 내용이며, 결정 근거는 `docs/adr/`와 이슈에 있다.

# 7. 하루 1기록: KST 기준, 잠금 대신 오늘 기록 대체

- 상태: Accepted
- 날짜: 2026-10-16

## 배경

메인 화면을 주간 포스터 캐러셀로 재설계하면서(`docs/design/home-mockup.html`) "날짜 한 칸 = 기록 하나"가 전제가 됐다. 그전까지는 하루에 여러 건이 저장됐고 `/`는 그중 마지막 1건만 보여줬다. 정할 것은 세 가지였다.

- 하루에 하나만 허용하는 방식: 두 번째 저장을 막을지, 대체할지
- "하루"의 기준 시간대
- 규칙을 어디서 강제할지: 앱 코드 또는 DB

## 결정

1. **하루 1기록, 오늘 기록은 대체 가능.** 같은 날 다시 저장하면 새 행을 만들지 않고 기존 행을 대체한다. 대체 시 `created_at`을 저장 시각으로 갱신하고, `ai_comment`를 비워 코멘트를 새로 생성하며(ADR-0006 흐름 재사용), `mood_source`도 새 선택값으로 쓴다. 지난날 기록은 대체하지 않는다.
2. **하루의 기준은 KST(Asia/Seoul).** 브라우저·서버 시간대와 무관하다. KST는 서머타임이 없는 UTC+9라서 오프셋 계산만으로 충분하다 (`shared/lib/date/kst.ts`).
3. **DB 제약으로 강제한다.** `records.record_date`(`(created_at at time zone 'Asia/Seoul')::date` 생성 컬럼)에 `unique (user_id, record_date)`를 건다. 저장은 `upsert(onConflict: "user_id,record_date")`로 원자적으로 처리한다. 새 저장은 항상 "지금"의 행이므로 충돌 대상은 오늘 행뿐이고, 지난날 기록은 저장 경로로 바뀌지 않는다.
4. **생성 중 대체 경쟁을 막는다.** 코멘트 생성이 도는 중에 같은 행(같은 id)이 대체되면 옛 메모의 코멘트가 새 내용에 붙을 수 있다. `generateDailyComment`는 읽은 시점의 메모와 같은 행에만 코멘트를 저장한다.

### 검토한 대안

| 대안 | 판단 |
|---|---|
| 하루 1기록을 잠근다 (두 번째 저장 거부) | 잘못 고른 곡을 고칠 방법이 없어 부담이 크다. 대체 가능이 기록 부담을 줄인다. |
| 표현식 유니크 인덱스 `(user_id, (created_at at time zone ...)::date)` | 제약은 같지만 supabase-js `upsert`의 `onConflict`에 표현식을 쓸 수 없어 원자적 대체가 안 된다. |
| 앱에서 삭제 후 재삽입 | 두 요청이 분리돼 원자적이지 않고, 중간 실패 시 기록이 사라진다. 행 id도 바뀐다. |
| 사용자 로컬 시간대 기준 | 기기마다 하루 경계가 달라 같은 기록이 다른 날로 묶이고 DB 제약을 걸 수 없다. |

## 결과

**긍정적**

- 날짜 하나에 기록 하나라서 캐러셀·달력·상세 패널이 날짜 키로 단순하게 묶인다.
- 중복은 DB가 막는다. 앱 버그나 동시 요청에도 하루 2건이 생기지 않는다.
- `created_at`을 갱신하므로 "기록 시각"과 코멘트 "생성 중" 판정이 마지막 저장을 기준으로 맞는다.

**부정적 / 트레이드오프**

- 대체하면 이전 내용(곡·메모·코멘트)은 사라진다. 이력은 남기지 않는다.
- 도입 시 기존 하루 중복 6건을 최근 1건만 남기고 삭제했다 (적용 전에 백업). 되돌릴 수 없다.
- DB 제약은 `saveRecord` 경로만 보호한다. RLS UPDATE 정책(`records_update_own`)은 소유자가 지난날 행의 내용도 직접 UPDATE할 수 있다. 서버 액션은 지난날 행을 건드리지 않지만 데이터 수준의 잠금은 아니다. 코멘트 재시도(`ai_comment`만 갱신)도 지난 기록에 필요해서 트리거로 막지 않았다.
- 마이그레이션을 SQL Editor로 적용했다면 마이그레이션 이력 테이블에 남지 않는다.

## 재검토 조건

- 사용자가 하루에 여러 곡을 남기고 싶어 할 때(예: 곡 목록 / 플레이리스트형 기록)
- 해외 사용자가 생겨 KST 하루 경계가 문제될 때 → 사용자별 시간대 저장
- 지난날 기록 직접 UPDATE가 실제 문제가 될 때 → 내용 컬럼 UPDATE를 막는 트리거 검토

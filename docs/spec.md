# Moodi - 프로젝트 기획서

## 개요
기분에 맞는 음악을 기록하고, 팔로우한 친구들과 실시간으로 음악 취향을 공유하는 소셜 음악 다이어리 서비스.
AI가 메모를 분석해 기분 태그를 추천하고, 하루의 기록을 감성 코멘트로 요약해주는 기능을 포함한다.

## 구현 현황 (2026-10-16 기준)

| 기능 | 상태 | 비고 |
|---|---|---|
| 1. 인증 | 완료 | 로그인 전용, 기본 차단 |
| 2. 음악 기록 | 완료 | 하루 1기록(KST), 오늘 기록 수정 |
| 3. AI 기분 태그 추천 | 완료 | Gemini Flash-Lite |
| 4. AI 오늘의 감성 코멘트 | 완료 | 서버에서 `after()`로 생성 |
| 5. 메인 화면(주간 포스터 캐러셀) | 완료 | 데스크톱 우선, 모바일 배치는 후속 |
| 6. 실시간 피드 | 미착수 | 2차 범위 |
| 7. 달력 히스토리 | 완료 | |
| 8. 소셜(팔로우·유저 검색·프로필) | 보류 | `follows`, `likes` 테이블만 생성됨 |

## 기술 스택
- **Frontend**: Next.js 16, TypeScript, Tailwind CSS, TanStack Query (Zustand는 설치만 되어 있고 아직 쓰지 않음 — 여러 화면이 공유하는 클라이언트 상태가 아직 필요하지 않았다)
- **Backend**: Supabase (DB, Auth, Realtime, Storage)
- **External API**: iTunes Search API (Apple) — 음악 검색, 앨범아트, 30초 미리듣기 (인증 불필요)
- **AI**: LLM API (현재 Gemini Flash-Lite 무료 티어, `MoodSuggester` 인터페이스 뒤에서 교체 가능 — `docs/adr/0005-llm-provider-gemini.md`) — Next.js Route Handler를 통한 서버사이드 호출

## 핵심 기능

### 1. 인증
- Supabase Auth 이메일 로그인/회원가입
- 프로필 설정 (닉네임, 프로필 이미지)
- 접근 정책: 로그인 전용 서비스. `/login`, `/signup`만 공개이고 그 외 모든 경로와 `/api/*`는 로그인이 필요하다(기본 차단, `/api/*`는 401). 로그인했어도 프로필이 없으면 프로필 설정으로 보낸다 (`proxy.ts`)

### 2. 음악 기록
- iTunes Search API로 음악 검색
- 오늘의 음악 등록
  - 곡명, 아티스트, 앨범아트, 30초 미리듣기
  - 기분 태그 선택 (설레는, 차분한, 신나는, 우울한, 집중되는)
  - 한 줄 메모
- 하루 1기록: 하루의 기준은 KST이고, 같은 날 다시 저장하면 오늘 기록을 대체한다(AI 코멘트도 새로 생성). 지난날 기록은 바꾸지 않는다 (`docs/adr/0007-one-record-per-day.md`)
- 오늘 기록 수정: `/record?edit=1`로 오늘 기록의 곡·무드·메모를 채워 연다. 저장하면 오늘 기록이 대체된다. 수정 중에는 AI 무드 제안을 다시 요청하지 않고, 무드를 바꾸지 않으면 기존 `mood_source`를 유지한다. 오늘 기록이 없으면 새 기록 화면으로 열린다
- 공개 범위: 전체 공개 고정

### 3. AI 기분 태그 추천
- 사용자가 메모를 입력하면(debounce 후) 메모 텍스트를 LLM에 전달해 5개 기분 태그 중 가장 어울리는 태그를 추천
- 추천 결과는 배지 형태로 표시되고, 사용자는 그대로 채택하거나 직접 다른 태그로 변경 가능
- 저장 시 `mood_source`(`user` | `ai`)를 함께 기록 — 사용자가 AI 제안을 얼마나 채택하는지 데이터로 남길 수 있음
- API: `POST /api/ai/mood-suggest { memo, trackName, artist } → { suggestedMood, reason }`

### 4. AI 오늘의 감성 코멘트
- 기록이 저장되면 그날의 곡 + 무드 태그 + 메모를 조합해 LLM이 한 줄 코멘트를 생성 (예: "잔잔하게 스며드는 하루였네요")
- 생성은 비동기로 처리 — 기록 저장은 즉시 완료되고, 코멘트는 스켈레톤 UI 이후 도착하는 대로 갱신 (낙관적 업데이트 + 스트리밍 UX 어필 포인트)
- 달력 화면에서 날짜 클릭 시 해당 코멘트를 툴팁/카드로 노출
- 톤은 메모의 구체적 표현을 짚어 되돌려주는 "거울" 한 문장이며, 메모가 없으면 만들지 않는다. 마음이 많이 힘든 메모에는 고정 문구를 쓴다 (`docs/adr/0006-ai-comment-policy.md`)
- 생성은 기록 저장 직후 서버가 시작하고(`after()`), 재시도용으로 API를 둔다. 서버가 `recordId`로 기록을 읽어 만들고 `records.ai_comment`에 저장한다
- API: `POST /api/ai/daily-comment { recordId } → { comment }`

### 5. 메인 화면 (주간 포스터 캐러셀)
- `/`는 내 최근 7일(오늘 포함, KST)을 날짜별 포스터로 보여주는 캐러셀이다. 오늘에서 시작하고, 이동은 이전/다음 버튼·키보드(←/→)·드래그·날짜 스트립으로 하며 자동 회전은 없다
- 포스터 3종: 기록 있음(앨범 아트·곡·아티스트·미리듣기) / 지난날 기록 없음(점선, 동작 없음) / 오늘 기록 없음(+ 아이콘, 눌러서 `/record`로 이동)
- 가운데 포스터의 무드 색이 배경으로 번진다
- 선택한 날의 상세는 우측 패널에 보인다: 곡, 무드, 메모(2줄), AI 코멘트(4줄)는 넘칠 때만 "전체 보기", 기록 시각과 무드 선택 방식(AI 제안 / 직접), 오늘 기록이면 수정 버튼. 1100px 이하에서는 패널이 숨겨지고 캐러셀 아래에 메모 1줄·코멘트 3줄 고정 영역으로 대신 보여준다
- 레이아웃: 761px 이상은 사이드바 | 본문 | 우측 패널 3열(1100px 이하에서는 사이드바가 아이콘 레일로 접히고 패널은 숨김), 760px 이하는 상단바 + 드로어. 모바일 캐러셀·패널 배치는 후속 작업
- 시각 설계: `docs/design/home-mockup.html`

### 6. 실시간 피드 (Supabase Realtime) — 미착수
- 팔로우한 유저가 음악을 기록하면 피드에 실시간으로 표시
- 좋아요 반응 (실시간 카운트 업데이트)
- 팔로우 기능이 생기면 메인 화면 우측 패널에 친구 섹션으로 붙인다

### 7. 달력 히스토리
- 날짜별로 내가 기록한 음악 조회
- 달력에 기분 태그 컬러로 시각화
- AI 코멘트 노출

### 8. 소셜 — 보류
- 단방향 팔로우 (팔로우/팔로워 목록)
- 유저 검색 (닉네임 기준)
- 유저 프로필 페이지 (기록한 음악 목록 공개)

## 페이지 구성
- `/` 내 최근 7일 주간 포스터 캐러셀 + 선택한 날 상세 패널
- `/record` 오늘의 음악 기록 (왼쪽 포스터 라이브 미리보기 + 오른쪽 폼: 메모 → 기분 → 저장, AI 기분 추천 포함, `?edit=1`은 오늘 기록 수정)
- `/diary` 내 음악 달력 (AI 코멘트 포함)
- `/search` 음악 검색 (유저 검색은 미구현)
- `/login`, `/signup` 공개 인증 페이지, `/profile/setup` 최초 프로필 설정
- `/profile/[id]` 유저 프로필 (미구현)

## DB 테이블 구조 (Supabase)
- `users` 유저 정보 (id, nickname, avatar_url)
- `records` 음악 기록
  - id, user_id, track_id, track_name, artist, album_art, preview_url
  - mood, mood_source(`user`|`ai`), memo
  - ai_comment (nullable, 비동기 생성)
  - created_at
  - record_date (생성 컬럼, `created_at`의 KST 날짜) — `unique (user_id, record_date)`로 하루 1기록 강제
- `follows` 팔로우 관계 (follower_id, following_id) — 테이블만 생성됨, 기능 미구현
- `likes` 좋아요 (user_id, record_id) — 테이블만 생성됨, 기능 미구현

## AI 연동 설계 메모
- API 키 보호를 위해 클라이언트에서 LLM을 직접 호출하지 않고, Next.js Route Handler를 프록시로 사용 (외부 음악 API도 클라이언트에서 직접 호출하지 않고 Route Handler 경유 — iTunes는 키가 없지만 rate-limit 완화·서버 캐시 목적)
- mood 추천은 동기 호출(기록 저장 전 즉시 응답 필요), 코멘트 생성은 기록 저장 후 비동기(fire-and-forget + 클라이언트 재조회)로 분리해 저장 흐름이 AI 응답 속도에 막히지 않도록 설계
- LLM 호출 실패 시 mood 추천은 조용히 스킵(사용자가 수동 선택), 코멘트는 재시도 버튼 노출 — AI 기능이 핵심 플로우(기록 저장)를 막지 않는 것을 원칙으로 함

## 개발 순서

### MVP (1차, 목표 1개월)
1. ✅ Supabase 프로젝트 세팅 + DB 테이블/RLS 정책 생성
2. ✅ Auth 구현 (로그인/회원가입/프로필 설정)
3. ✅ iTunes Search API 연동 (음악 검색)
4. ✅ 음악 기록 기능 + AI 기분 태그 추천
5. ✅ 달력 기반 내 기록 조회 + AI 코멘트 노출
6. ⏸ 팔로우 & 유저 검색 (기초) — 보류

추가로 완료: 하루 1기록(KST, ADR-0007), 전역 내비게이션 셸(사이드바 / 상단바), 메인 화면(주간 포스터 캐러셀)과 오늘 기록 수정.

### 2차 (여유 있을 시) — 미착수
7. Supabase Realtime 피드
8. 좋아요 실시간 반응
9. UI 다듬기, 접근성/성능 보완
